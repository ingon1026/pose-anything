# 부분화소 경계 — 후보 `hull_layer`, 조건부로 이기고 **지금 조건에서는 진다** (2026-08-25)

→ 2026-09-02 재개 절 참고

풋프린트 폭 부족 **5.24mm** 는 두 항으로 닫힌다 — **래스터 양자화 0.79px +
화소중심 규약 1px = 1.79px**([image_size](image_size_2026-08-21.md) 행수 절,
`geometry.py` `obb_on_plane` docstring). 둘 다 **"화소를 센다"** 에서 오므로
처방이 하나다: **부분화소 경계.**

그 처방을 조사했다. **후보를 찾았고, 무노이즈에서 이기고, RealSense 노이즈
아래에서는 진다.** 결론은 **현행 유지**이고, 아래는 그 기각 이유다.

> **결론 한 줄**: `hull_layer` 는 **isaac 에서 5.24 → 2.31mm** 로 이긴다.
> 지는 이유는 **껍질 기반 max 통계량이 산발 노이즈 화소에 부풀려지기 때문**이고
> (실기에서 직접 관측), 합성 대조로는 그 역전이 flip **1%** 에서 일어나는데
> **RealSense 3개 bag 이 어느 환산에서도 1% 를 넘는다.** 저장소 규칙
> ("통과 영역의 최대 오차", `docs/README.md` §5)이 현행 유지를 가리킨다.

---

## 1. 후보 `hull_layer` — 유일한 생존 후보 (확인)

`minAreaRect` 를 그대로 쓰되, 네 변을 각각 **"최외곽 한 켜(두께 = 화소 피치)
안의 평균 후퇴량 `m`"** 만큼 밀어낸다:

```
δ = pitch/2 − m          pitch = median(z)/fx   (관측값)
```

- **축 정렬**이면 켜가 한 점에 몰려 `m → 0` → `δ → pitch/2` (최대 보정)
- **비스듬**하면 후퇴량이 켜 안에 퍼져 `m → pitch/2` → `δ → 0` (보정 없음)

→ **각도가 자동으로 처리되고 자유 파라미터가 없다.** `1/2` 은 화소 반폭이고
`pitch` 는 관측값이라, 튜닝할 상수가 하나도 없다. 이것이 다른 후보와 갈리는
지점이다.

### 무노이즈 최악 오차

| 방식 | 최악 오차 |
|---|---|
| **`hull_layer`** | **2.31mm** |
| `centers + 1px` | 2.97mm |
| `corners` | 4.06mm |
| **현행** | **5.24mm** |

### 구멍·가림 내성 (이것이 다른 후보를 죽였다)

`hull_layer` 는 **껍질 기반**이라 구멍·가림에 **면역**이다. 경쟁 후보는 아니다:

| 후보 | 구멍 | 가림 |
|---|---|---|
| 2차 모멘트 | **+5.54 / −2.73** (배치가 **부호를 뒤집는다**) | — |
| 면적 기반 | **−7.13 / −10.06** | −6~−10mm |

부호가 배치에 따라 뒤집히는 추정량은 게이트로 못 쓴다
(`docs/README.md` §5 "씬 안에서 순위가 역전되면 문턱이 아예 존재하지 않는다"
와 같은 이유다).

### 모형 무관 출력 — 그리고 **회수할 수 없는 몫** (확인)

```
hull_layer = (행수) × pitch
```

isaac 은 **18행**이므로 **52.69mm** 다. **정답 55.00 대비 남는 2.31mm 는 고칠 수
있는 오차가 아니다** — *"참 18.79px 짜리 막대에 18행만 켜졌다"* 는 **센서의
성질**이고, **이진 마스크에서는 원리적으로 복구 불가**다. 52.69 를 "절반만 고친
값" 으로 읽으면 안 된다. **부분화소 경계가 회수할 수 있는 전부가 5.24 → 2.31 이다.**

### 무조건 상한 (확인)

```
|hull_layer 오차| ≤ |현행 오차| + 2.93mm
```

변마다 보정량이 `[0, pitch/2]` 이고 합이 `[0, 1.0]px` 이라, **관측된 최대가
이론 상한과 정확히 일치**한다. → **이 교환은 ±1px 안에서 일어난다.** 실패해도
자릿수가 튀지 않는다는 뜻이고, 그래서 아래 기각이 "위험해서" 가 아니라
**"이득이 노이즈에 먹혀서"** 다.

## 2. 기각 사유 — **껍질 기반 max 통계량이 산발 노이즈 화소에 부풀려진다** (확인)

주된 사유는 비율 수치가 아니라 **실기 데이터에서 직접 관측된 기전**이다.
`hull_layer` 가 쓰는 extent 는 **max 통계량**이라 산발 화소 한두 개가 그대로
결과가 된다:

- 물체 **자신의 depth(±2mm)** 로 조여도 마스크 밖에 **14~41화소**가 남는다
- 그중 **투영축 끝단 두어 개**가 **+2.5~2.9px** 를 만든다
- **isaac 은 정확히 0** 이다

**이것과 §3 의 "부호를 못 잰다" 는 같은 한 문장의 두 얼굴이다** — 기전이 하나라
두 관측이 서로를 지지한다. 우연히 겹친 두 실패가 아니다.

### 뒷받침 — 합성 sweep 대비 대조 (교차점 <1%)

위 기전이 얼마에서 이득을 삼키는지 합성으로 대조했다. 가장자리 flip 비율
(관측당 `p`. 마스크 정의·환산 배율 **1.8~1.9×** 는 주입 실험으로 측정):

| bag | flip |
|---|---|
| isaac | **0.21 ~ 0.36%** |
| test2 | **2.80 ~ 3.86%** |
| test4 | **1.67 ~ 8.81%** |
| test3 | **1.56 ~ 6.88%** |

**교차점이 1% 아래다:**

| flip | 현행 최악 | `hull_layer` 최악 |
|---|---|---|
| 0% | 5.24 | **2.31** |
| **1%** | **5.24** | 6.47 |
| 5% | **5.32** | 7.82 |

> **⚠ 이 교차점은 낙관적이다 — `prod` 가 `union` 보다 4배 시끄럽다.**
> 위 sweep 이 흔든 축은 `union` 인데 **파이프라인이 실제로 마주하는 것은
> `prod`** 이고, `prod` flip 은 test4 **3.68 → 14.1%**, test3 **3.43 → 11.0%**
> 다. **즉 실제 교차점은 이 표가 시사하는 것보다 더 뒤에 있다** — 표의 1% 를
> "파이프라인 조건에서 잰 값" 으로 인용하지 말 것.

**RealSense 3개 bag 이 두 마스크 정의·환산 양끝 어디서도 1% 를 넘는다.**
저장소 규칙은 순위 능력이 아니라 **"통과 영역의 최대 오차"** 이므로
(`docs/README.md` §5), 최악 오차가 **5.24 → 6.47mm 로 나빠지는** 변경은 채택
못 한다. → **현행 유지.**

### 기전 — z밴드가 depth 노이즈를 새로 들인다 (확인)

`mask_depth_to_points`(`geometry.py:60-73`)의 z밴드가
`median ± max(3·1.4826·MAD, …)` 라, **RealSense depth 가 흔들리면 남는 화소
집합이 숨을 쉰다.** 침식은 마스크 노이즈를 지우지만 **z밴드는 depth 노이즈를
새로 들인다** — 그래서 `prod` 가 `union` 보다 시끄럽다.

### 수선이 없다 (확인 — delta 분해)

노이즈 취약성의 원인이 **가산이지 최댓값이 아니다**:

- 앵커 탈취분: **−0.05 ~ −0.76mm** (오히려 **음수**)
- 지배항 껍질 팽창분: **+1.95 ~ +5.19mm** — **두 후보에 똑같이 실린다**

→ `hull_layer` 쪽만 손봐서 고칠 여지가 없다. **후보를 바꿔도 같은 항을 진다.**

## 3. 두 번째 미결 — **부호를 RealSense 에서 못 잰다** (확인된 실패)

> **⚠ 표현 주의 — *"껍질이 바깥이라 방향이 틀렸다"* 로 적지 말 것.**
> 그 증거가 **없다.** RealSense 에서는 부호가 **어느 쪽으로도** 확인되지
> 않았으므로 *"바깥이다"* 도 주장할 근거가 없다. 정확한 진술은 이것이다:
> **방향은 isaac 에서 확인됐다. 그리고 노이즈가 1% 를 넘는 씬에서는 방향의
> 옳고 그름과 무관하게 껍질 방법이 성립하지 않는다.**

### isaac: 껍질 안쪽 확정
9개 물체 전부 `out_L` **−2~−8px**, `out_W` **−1~−2.5px**, 마스크 밖 성장
**0px**. **진실 앵커까지 있다** — 참값 **18.79px** 대비 껍질 **17px span** 이다
(같은 것을 행으로 세면 **18행**이고, `span = 행수 − 1` 이 바로 이 문서가 다루는
화소중심 규약이다. **두 수를 서로 바꿔 쓰지 말 것**).

### 방법이 회전에 막힌 것이 아니다 (확인)
부호 측정은 **행수가 아니라 `minAreaRect` 주축 투영 px extent** 로 했고
**회전 물체에서 잘 돈다** — isaac 에서 행수와 일치 검증했다(마스크 **20** /
core **18**). **"회전 때문에 못 쟀다" 로 적으면 틀린다.** 막은 것은 아래
z밴드다.

### test2 / test4 / test3: 판정 불가 — 세 갈래로 막힌다

1. **밴드가 지지면을 먹는다.** 물체-지지면 분리 med **18 / 22 / 1mm** 인데
   z밴드 far 반폭이 **31 / 18 / 27mm** 다. `geometry.py:64-72` 가 경고한 바로
   그 조건이다
2. **판정 가능한 프레임만 골라도 성장 화소가 옆면이 아니다** — 비대칭도
   **0.17~0.29** 로 사방 대칭이고, 예상 옆면폭의 **수백 배**이며, depth 가
   상면과 지지면 **사이**에 있다
3. **`tol=2mm` 로 조여도 14~41화소가 남는다** — 그게 **측정된 가장자리
   노이즈가 예측하는 자릿수**다. isaac(0.3%)은 정확히 **0** 이다

**덧붙여 CC 팔은 `edge_frac` 이 부호를 정한다** — test2 가 `L+0.8 / W+8.6`
(ef 0.35) → `L+15.7 / W+33.5`(ef 0.65). **isaac 만** `L−2.0 / W−2.0` 으로
안정적이다. 문턱이 부호를 뒤집으면 그 측정은 결론이 아니다.

### ⭐ 이 실패 자체가 결과다

부호 측정이 RealSense 에서 깨지는 이유와 `hull_layer` 가 RealSense 에서 지는
이유가 **같다** — **껍질 기반 max 통계량이 산발 노이즈 화소에 부풀려지는 것**
(§2). 두 측정이 같은 경계선에서 갈리며 **서로를 지지한다.** 우연한 실패가
아니고, **이것이 기각의 주된 사유**다 — flip 1% 교차점은 그 기전을 합성으로
대조한 뒷받침이다.

### 부호 질문은 사실 둘이다 — 하나는 이미 답이 나와 있다

| | 질문 | 상태 |
|---|---|---|
| **(1)** | 중심 껍질이 관측 화소집합의 **면적 껍질 안쪽**인가 | **기하 항등식 — 모든 bag 에서 언제나 참.** 이 몫에 대해 `hull_layer` 는 **무조건 옳다** |
| **(2)** | 관측 화소집합이 **참 물체를 1px 넘게 과피복**하는가 | **정답이 있어야 답한다.** RealSense 는 물리 실측이 없어 **원리적으로** 못 잰다 |

**`hull_layer` 를 죽일 수 있는 것은 (2) 뿐이고, 막힌 것도 (2) 뿐이다.**
"못 쟀다" 가 아니라 **"어느 몫이 왜 막혔는지" 가 갈려 있다.**

## 4. 스칼라 보정은 **별도로** 죽었다 — `hull_layer` 와 무관한 두 이유

`+1px` 같은 고정 보정은 `hull_layer` 의 기각과 **다른 이유로** 죽는다. 둘을
같이 묶지 말 것.

### (a) 각 분포 — 실기는 축 정렬이 아니다 (확인, 629관측)

| 씬 | 각 |
|---|---|
| isaac | **0.00°** |
| test2 | med **16.99°** |
| test4 | med **18.97°** (p95 **37.4°**) |

**물체 하나로 충분하다** — test4 det1: 종횡비 3.36, 장축 168px, **35.43°**,
프레임간 sd **0.96°**. PCA 주축각과 **1.6° 안에서 일치**한다.

→ **"축 정렬이라 −2.93mm 가 온전히 걸린다" 는 isaac 의 성질이지 일반 명제가
아니다.** 출하 프리셋(672)이 도는 씬들은 centers 오차가 **−0.17 ~ −0.48mm** 인
각도 대역에 있다. 거기에 `+1px` 을 넣으면 **과보정**이다.

### (b) 위상 뽑기 — `5.24mm` 는 얼어붙은 21% 뽑기다 (확인)

0° 에서 centers 오차는 **값이 둘뿐**이다:

| 값 | 확률 |
|---|---|
| **−1.79px** | **21%** |
| −0.79px | 79% |
| **위상평균** | **−1.000px** |

**즉 관측된 5.24mm 는 "0° 의 값" 이 아니라 21% 쪽 뽑기가 카메라 고정으로
얼어붙은 값이다.** 79% 쪽이었다면 부족이 **2.31mm** 였고, `+1.79px` 은
**+2.93mm 과보정**이 됐을 것이다.

→ **한 카메라 위치에서 잰 부족량을 그 조건의 상수로 읽으면 안 된다.**

## 5. 재개 조건 — 무엇이 들어오면 다시 여는가

**`test2` / `test4` 의 물리 실측(줄자)** 이다. 사슬은 이렇다:

```
물리 실측 → fp_harness.py 의 TRUTH 에 bag 추가 → 오차 필드가 켜짐
          → §3 의 (2) "참 물체를 1px 넘게 과피복하는가" 를 답할 수 있음
          → hull_layer 의 부호가 확정됨
```

**코드 변경은 `TRUTH` 에 bag 을 추가하는 것뿐이다.** 지금 막힌 것이 (2) 하나
뿐이므로, 그 하나가 풀리면 이 항목이 열린다.

**다만 §2 의 노이즈 기각은 별개로 남는다** — 부호가 확정돼도 flip 1% 교차점을
넘지 못하면 여전히 채택 못 한다. **두 잠금이 따로 있다.**

`docs/datasets.md` "Data still needed" 에 물리 실측이 이미 대기 항목으로 있다
(`docs/README.md` §4 "측정하면 답이 나오는 것" 의 *"test2 면내 크기 차이의 정오
— 실물 줄자 실측 필요"*).

## 6. 이 조사에서 났던 오진 — **기각 이유와 함께 남긴다**

**"각도표가 서로 다른 오차 예산을 섞었다"** 고 선언하고 `geometry.py`
docstring 에 경고까지 박았다. **틀렸다.**

`−3.03mm`(합성 **위상평균**)와 `−5.21mm`(실데이터 **고정 위상**)는 **다른 예산이
아니라 같은 양의 두 통계량**이다. 합성에 래스터 항이 빠진 게 아니라, **평균에서
21:79 로 섞였을 뿐**이다(위 §4-b).

**경위**: 형제 팀이 반박 → 계산 확인 → 양쪽 철회. **오늘 두 번째로 팀 간
교차 확인이 오진을 잡았다.** 교훈은 `docs/README.md` §5 에 넣었다 —
*"같은 양의 두 통계량(평균 vs 특정 조건값)이 다른 값을 내는 것을 '다른 양'
으로 오진하지 말 것. **위상·조건 분포를 먼저 물을 것.**"*

## 2026-09-02 재개 — 확률장 등고선 (soft_footprint)

§5 의 재개 조건(`test2`/`test4` 물리 실측)은 아직 안 왔다. 대신 처방 자체
("부분화소 경계")를 다른 경로로 다시 시도했다 — 이진화 후 마스크가 아니라
**이진화 전 SAM3 확률장**을 쓴다.

### 기전

`hull_layer`(§1)와 달리 **max 통계량이 아니라 경계 전체**를 쓴다. 이진화 전의
SAM3 확률장(logit sigmoid)의 **0.5 등고선**(skimage `find_contours`, 부분화소)을
경계 위치로 쓰고, 각 등고선 점의 높이는 그 점 안쪽 3×3 의 실제 depth 중앙값으로
잡아 **점마다 자기 높이 평면에 광선 투사**해 `minAreaRect` 를 건다. 두께는 기존
`obb_on_plane` 의 q98 그대로. 구현: `geometry.contour_obb_on_plane`, 플래그
`soft_footprint`(pipeline·`run_offline.py --soft-footprint`·노드·launch),
**기본 off**.

### 개발 중 잡힌 실패 양식

전부 고쳐졌고 `geometry.py` `contour_obb_on_plane` docstring 에도 있다.

1. 등고선 전부를 상면 평면(thk)에 투사 → 화면 끝 블록(37° 사선)의 옆면이
   상면으로 끌려 올라가 L +19~22 (중앙 블록은 199).
2. 높이 띠로 상면만 게이트 → 파인 블록은 실루엣이 한 높이가 아니라(끝 55·긴변
   25) 양 끝 캡만 남아 L=56.
   → 1·2 의 처방이 "점마다 자기 높이" 다. 현행 경로가 맞는 이유(픽셀마다 실제
   depth)와 같다.
3. 게이트 없음 → 마스크가 블록 사이 틈(벨트)으로 새 L +15 → h ≥ 5mm 게이트.
4. 가장 긴 등고선 → 마우스 조각 → 면적 최대 등고선.
5. ⚠ 검출 0개 프롬프트에서 bf16 → numpy 변환 실패로 **기본 경로까지** 죽음
   (test4 손 가림 프레임) → `.float()`. 174 테스트가 SAM3 를 안 돌려 못 잡았다 —
   실기 bag 이 잡았다.
6. **필드 게이트의 보간 왜곡.** 확률장을 게이트 밖에서 0 으로 누르면 marching
   squares 가 안쪽 화소(0.9)와 0 사이를 보간해 경계를 안쪽으로 당긴다 — 이웃의
   참값(0.4)과 보간했어야 한다. 합성 0° 에서 −1.74mm, Isaac W −1.0mm 가 전부
   이것이었고, **중간에 나온 "201.9 / 54.0" 은 이 왜곡이 SAM3 과피복을 우연히
   상쇄한 값이다 — 인용 금지.** 처방: 게이트를 **점에** 건다 — 등고선은 순수
   확률장에서 뜨고, 각 점의 안쪽 법선 0.75px 화소가 (prob>0.5 & h≥h_min) 이
   아니면 그 점을 버린다. RealSense 에서는 depth 구멍이 물체 안에도 있어
   필드 게이트면 등고선이 안으로 파고드는 것도 이 처방이 막는다.
