# 발행 공백 원인 분해와 `PUB_POS_STD_MAX` 근거 (2026-08-24)

test5(1,015프레임)에서 커버리지가 51~75%, 최대 공백이 13.4초로 나와
`datasets.md` 기준(재개 지연 중앙 0.3s, 90% 1.7s, **최대 3.2s**)의 4배처럼
보였다. 원인을 계측으로 분해한 기록이다.

## 결론 먼저

**"기준의 4배"는 다른 양을 비교한 것이었다.** `datasets.md` 의 3.2초는
**완전 가림 이후 재개 지연**이고, 여기서 측정된 13.4초는 **부분 가림이 지속된
시간**이다. 재개 자체는 물체가 드러나는 즉시 일어난다.

## 공백의 구성 (test5)

```
라벨            발행   침입보류  융합기각  발행게이트
black bag       669      117      150       71
book            568      104      171      172
gray notebook   753       98      110       54
keyboard        511      122      280       95
```
(동결·마스크없음·절단시드차단·점군부족은 사실상 0)

### 융합 기각은 정당하다 — 실제로 가려져 있었다
기각 프레임의 풋프린트 편차를 직접 기록해 확인했다:

| 라벨 | 기각 프레임 | `dev < -TAU` | 편차 중앙 | p10 |
|---|---|---|---|---|
| black bag | 251 | 52% | −0.154 | −0.947 |
| book | 196 | 58% | −0.411 | −1.177 |
| gray notebook | 166 | 85% | −0.360 | −0.971 |
| keyboard | 326 | 67% | −0.532 | −1.398 |

편차 −0.53 은 면적비 0.59(**41% 가려짐**), p10 −1.4 는 0.25(**75% 가려짐**)다.

**긴 갭은 면적 증가로 끝난다** — book +60%, keyboard +47%. 물체가 드러나는
순간 재개된다는 뜻이고, 이는 2026-08-21 에 판정을 대칭→비대칭으로 바꾼 결정의
사후 검증이기도 하다(대칭이었으면 증가 방향도 막혀 영영 못 나왔다).

### 발행 게이트는 주범이 아니다
최장 미발행 구간의 구성: keyboard 13.22s 중 융합기각 **71%**, book 11.48s 중
**55%**. 발행 게이트는 17~32% 이고, 그중 상당수가 1프레임 산발(33~45개, 33ms)
이라 재개 지연에 기여가 없다.

긴 구간의 정체는 `CONFIRM_N` 재승격이 아니라 **`pos_std` 회복 대기**다.
침입보류·융합기각 중에는 `predict` 만 돌아 P 가 자라고, 관측이 재개돼도
σ 가 문턱 아래로 내려올 때까지 발행이 막힌다.

## `PUB_POS_STD_MAX` 근거 — 지금까지 없었던 것

주석에 "로봇 사양 확정 전 잠정"이라고만 적혀 있던 `0.02` 에 실측 근거를 만들었다.
**σ 는 실제 오차의 좋은 예측자다** (test5, 정지 씬이므로 초반 중앙값을 기준으로
한 이동량을 오차로 본다):

| σ 구간 | 오차 중앙 | 30mm 초과 비율 |
|---|---|---|
| 0~5mm | 1~9mm | **2~8%** |
| 5~10mm | 5~28mm | 13~44% |
| 10~20mm | 4~46mm | **16~76%** |
| 20~50mm | 15~48mm | 35~66% |
| 50mm~ | 40~380mm | 70~100% |

**현행 문턱(20mm)은 관대하다** — 10~20mm 구간이 이미 30mm 초과를 16~76% 낸다.

문턱별 교환비(σ 조건만 적용한 값. 실제 발행은 다른 `publishable` 조건 때문에 더 적다):

| 라벨 | σ<20mm (현행) | σ<10mm | σ<5mm |
|---|---|---|---|
| black bag | 891f / 중앙 18mm / 28% | 740f / 14mm / 18% | 536f / 9mm / **8%** |
| keyboard | 684f / 2mm / 16% | 518f / 1mm / 12% | 365f / 1mm / **7%** |
| book | 750f / 1mm / 6% | 628f / 1mm / 4% | 543f / 1mm / 2% |
| gray notebook | 1005f / 1mm / 7% | 928f / 1mm / 5% | 779f / 1mm / 2% |

**커버리지 40~47% 를 잃고 오염을 1/3 로 줄이는 교환**이다. book·notebook 은
현행에서도 이미 좋고(중앙 1mm), 문제는 black bag(28%)과 keyboard(16%)다.

### 값을 바꾸지 않은 이유
그리퍼 오차 허용치가 없으면 이 교환의 어느 쪽이 옳은지 정할 수 없다.
`docs/truncation_unify_2026-08-24.md` 의 발행 정책 문제와 같은 지점이고,
**로봇 연동 요구사항(9월, WBS 7.5) 확정 후에 이 표를 보고 정하는 것이 맞다.**
`0.01` 이 유력 후보다 — 커버리지 손실 17~24% 로 오염을 28→18%, 16→12% 로 낮춘다.

## 계측 아티팩트 정정 — 검출 실패는 0이 아니었다

초기 계측에서 "트랙 미매칭 0프레임"이 나와 *"검출은 멀쩡하고 문제는 파이프라인
내부"* 라고 결론냈는데, **그것이 틀렸다.** `matched` 를 `_with_frozen()` 결과로
판정해 동결 트랙까지 포함시킨 탓이다. 검출 dict 에서 직접 세니:

| 라벨 | 키프레임 중 검출 0개 |
|---|---|
| book | **22%** |
| gray notebook | **22%** |
| keyboard | 11% |
| black bag | 4% |

`datasets.md` 가 적어둔 **"weak-prompt 물체의 multi-second gap 은 detection
-threshold 문제지 occlusion logic 이 아니다 — 프롬프트 교체가 먼저"** 가 여전히
유효하다. 성급히 기각했던 가설이다.
